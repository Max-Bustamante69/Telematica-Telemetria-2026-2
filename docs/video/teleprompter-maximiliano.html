Presentación y problema

Hola, somos Maximiliano Bustamante y Valeria Hornung, y este es nuestro proyecto de Telemática: una plataforma distribuida de telemetría. El problema es el de una organización con instalaciones en varios lugares, donde cada una tiene sensores que reportan temperatura, humedad, consumo de energía, vibración y el estado de los equipos. Todo eso tiene que llegar a un servidor central en la nube, y un operador tiene que poder consultar cualquier dispositivo y recibir una alerta cuando algo se sale de rango. Lo resolvimos con tres programas. Nodos de telemetría en Python que simulan los sensores. Un servidor central escrito en C, que corre dentro de un contenedor Docker en una instancia de Amazon EC2. Y un cliente operador, también en Python. Los nodos encuentran el servidor por un nombre DNS: telemetria punto digitdeck punto co. Ningún archivo del proyecto contiene la dirección IP.

02 · 02-max-protocolo.mp4

El protocolo TLP

Diseñamos un protocolo de aplicación propio, de texto, que llamamos TLP, Telemetry Line Protocol. Cada mensaje es una línea terminada en salto de línea, con campos separados por una barra vertical, y el primer campo es el tipo de mensaje. Un nodo se registra con REGISTER, su identificador, su ubicación y la lista de variables, y el servidor responde OK REGISTERED con el puerto UDP. Después el nodo envía TELEMETRY, identificador, número de secuencia, variable y valor, un datagrama por variable. Y el operador consulta con comandos como LIST NODES, GET LAST o GET STATUS; las respuestas de varias líneas terminan con END, para que el cliente sepa dónde acaba la respuesta sin depender del cierre de la conexión. Los errores llevan un código: 100 formato incorrecto, 101 comando desconocido, 102 nodo desconocido, 103 parámetro inválido, 104 nodo no registrado, 105 línea demasiado larga y 106 servidor lleno. La telemetría va por UDP porque cada nodo manda cinco datagramas cada dos segundos, perder uno no importa, y el número de secuencia nos permite contar exactamente cuántos se perdieron. El registro, las consultas y las alertas van por TCP porque necesitan confirmación y orden: una alerta perdida es un incidente que nadie atendió.

03 · 03-max-servidor.mp4

El servidor en C

El servidor está escrito en C, con sockets POSIX. Tiene dos sockets. Uno TCP en el puerto 5001: hace socket, bind, listen y accept, y por cada cliente que entra crea un hilo. Ese hilo lee hasta encontrar un salto de línea, porque en TCP un mensaje puede llegar partido o dos mensajes pueden llegar juntos. El otro socket es UDP, en el puerto 5000: recibe cada datagrama de telemetría con recvfrom, y solo responde, con sendto, si el nodo no está registrado. Todo el estado, nodos, mediciones y alertas, está en memoria y protegido con un mutex, porque varios hilos lo tocan a la vez. Dos detalles de robustez. Ignoramos la señal SIGPIPE, para que un operador que cierre a mitad de una respuesta no tumbe el servidor. Y al recibir SIGTERM cerramos los sockets de escucha, para que los hilos despierten y el proceso termine limpio. El servidor corre dentro de Docker. Aquí está docker ps en la instancia: el contenedor está arriba y el healthcheck dice healthy.

04 · 04-max-nube.mp4

Nube, DNS y Docker

El servidor está en Amazon EC2, en una instancia t3 micro con Ubuntu, en Virginia del Norte. El grupo de seguridad abre solo cuatro puertos: 22 para SSH, 5000 UDP para telemetría, 5001 TCP para operadores, y 8080 para la web. La instancia tiene una IP elástica, 100 punto 25 punto 236 punto 127, que no cambia aunque se reinicie. El nombre telemetria punto digitdeck punto co es un registro A en Cloudflare que apunta a esa IP, con el proxy apagado, porque el proxy de Cloudflare solo deja pasar HTTP. Lo compruebo en vivo con nslookup: el nombre resuelve a 100 punto 25 punto 236 punto 127. Ningún archivo del proyecto tiene esa IP escrita. Para desplegar, el código se copia a la instancia por SSH y se construye con docker compose. La imagen tiene dos etapas: una con gcc que compila, y otra con Debian mínimo que solo lleva el binario. Pesa 114 megabytes.
